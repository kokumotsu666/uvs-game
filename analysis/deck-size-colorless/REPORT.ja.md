# UVS v1.5 山札枚数・特殊無色カード比較実験

## 1. 実施概要

基準はmain `d757ca80709711ad9564898c39902f0fe001c411`。葛城対柳生／葛城対雲雀に対して30・35・40枚の各条件を1,000試合ずつ、計6,000試合実行した。各対面・条件で両座席各500、各座席の先攻P1/P2各250とした。予備120試合（本検証の先頭10seedずつを再利用）も異常0。本検証6,000試合のエラー・監視上限超過も0。予備対戦を本検証の集計には重複加算していない。

通常カード30枚、ルールv2、現行ソルバー（samples=24、iters=120、既定の重み・重撃方針）を固定。index.html・公開版は変更せず、VM内にだけ特殊処理を注入した。基準ソースのSHA256はmanifestに保存し、不一致なら実行を拒否する。

## 5. 解釈と比較上の注意

- 対柳生・射撃: 葛城勝率は 30枚 49.0% [45.9–52.1] → 35枚 40.4% [37.4–43.5] → 40枚 43.2% [40.2–46.3]。点推定で50%に最も近いのは30枚条件。
- 対雲雀・反撃: 葛城勝率は 30枚 76.8% [74.1–79.3] → 35枚 67.9% [64.9–70.7] → 40枚 63.0% [60.0–65.9]。点推定で50%に最も近いのは40枚条件。
- 雲雀のドロー時山札切れ敗北は617→450→286件と減少し、防御後の攻撃勝利は166→280→328件と増えた。一方、葛城の5ダメージ勝利は94→126→207件、「山札残数以上のダメージ」勝利は57→103→137件に増えており、山札切れ以外の勝ち筋への移行も観測された。
- 柳生もドロー時山札切れ敗北は158→37→4件に減ったが、葛城との勝率は30枚時点でほぼ互角だった。この特殊処理は対雲雀の偏りを縮める一方、対柳生では葛城不利側へ動くため、全対面へ一律採用する根拠にはならない。
- 使用不能カードを引く副作用も実測された。40枚条件の雲雀は1,000試合で2,568枚の無色を引き、602試合で少なくとも1枚引いた。山札切れの緩和と手札の死に札化は同時に起きている。

これは「通常カードを増やす35/40枚デッキ」の実験ではなく、山札下の使用不能カードが破壊を優先して受ける特殊条件の実験である。山札寿命・手札の死に札・破壊で失われる通常カード・ソルバーの判断が同時に変化するため、勝率差を単一要因の効果として分離できない。

ソルバーの判断ロジックは変更していないが、山札残数・手札枚数・未知手札サンプリングのプールには無色も含まれる。この入力変化でドロー評価や攻防判断が変わり得る。無色を認識する追加戦術や、未知手札サンプルから無色を除く補正は入れていない。

## 6. 特殊処理の仕様と変更差分

- 公開index.htmlは変更なし。新規ファイルはanalysis/deck-size-colorless以下のみ。runtime.cjsが元HTMLのscriptを順に評価し、DOM起動画面だけ省略する。
- CONFIG.deckSizeは通常30枚リストを選択するため30のまま固定。setupGameが通常30枚を毎試合シャッフルして初手4枚を配った直後、両者の残り通常26枚の下に無色を5/10枚追加する。これは「通常30枚＋末尾無色」から初手4枚を取る処理と同一で、通常カードの初手・順序と乱数消費は3条件で一致する。
- 無色は一意UID付きtype=colorless、属性は無、技なし、AT/DF/DP=0、アイコンなし、GPは0/0、効果なし。CARDSやDECKSの通常カード定義・種類・枚数は変更しない。
- ドローは既存drawをそのまま呼び、無色が手札へ入った実枚数だけ追加計測する。無色はbaseUsable/canAttack/canDefend/heavyOKの既存条件を満たさず、サポート使用・ゲージ配置・攻防・重撃・連撃に出せない。ソルバーの手札効用は0。
- VM内のmillを、追加カード定義が関数を捕捉する前に差し替える。破壊は山札内で最も上にある無色を優先し、不足分だけ通常カードを上から捨て札へ送る。通常カード同士の相対順は維持する。
- 破壊として扱う呼出し元は効果、ドラゴンベアード、葛城Lv4、葛城Lv5、雲雀Lv5。未知のmill呼出し元は黙って分類せずエラーにする。リミットブレイクは自分の山札を捨てる使用コストと解釈し、通常どおり上から処理し、破壊枚数と別計測する。
- 無色がないmillは元のmillへ委譲。30枚条件は既存シミュレーターの全2,000試合と、勝者・理由・ターン・最終状態・攻防/回復/重撃/連撃等の計測値が一致した。
- 山札下への戻し、通常の手札捨て、ダメージエリアへの移動等は元の処理のまま。無色は自身の効果を発動できないが、一般的な手札の捨て/入れ替え対象にはなる。初期配置後に通常カードが山札下へ戻ると無色より下に来る場合もあり、初期以外の並べ直しはしない。
- 各試合終了時に、無色の山札・手札・ダメージ・捨て札の合計が追加枚数と一致することを検査する。

## 7. 検査結果・再現方法

- test.cjs: 13シナリオ/配置検査に成功。無色優先・不足時の通常上からの破壊・空山札・自分の使用コスト・通常ドロー・禁止用途・山札下へ戻し・ダメージ移動・追加カード関数の捕捉・初期通常カード順序の一致を確認。
- 計測なしの元エンジンとも全4座席の代表seedで照合。さらに本検証の30枚条件2,000件は前回のmain-games.jsonl（分析コミット6d79eb8）から抽出したbaseline-reference.jsonlの全件に一致。
- 全条件の本検証6,000件は正常終了し、無色の枚数保存検査も全件通過。300手番・20,000判断・worker10分の監視上限超過なし。

```sh
node analysis/deck-size-colorless/test.cjs
node analysis/deck-size-colorless/run.cjs pilot
node analysis/deck-size-colorless/run.cjs main
python3 analysis/deck-size-colorless/summarize.py
```

Node 24以上、Python標準ライブラリのみ。既存結果は上書きを拒否するため再実行前に退避する。seedは1000000+[10,11,18,19][config]×10000+game、先攻はgame%2。条件間で同じ通常カード順序・seed・先攻を使う。各試合のsize/config/game/seed/first/winner/決着理由と実測値をJSONLへ保存。時刻と書込み順は再実行で変わり得る。

- 対人戦、ミラー戦、今回以外の対面、通常カードを追加する35/40枚構成、無色を全体シャッフルする構成、別CPUは未検証。
- 今回の3デッキに含まれない効果との相互作用を網羅的には検証していない。将来のカード・mill呼出し元には分類と追加検査が必要。
- ブラウザ・iPhone上での無色表示やUI操作は対象外。無色は実験VM内のみ存在し、公開ゲームには追加していない。
- 勝率差の原因を「山札延長」「破壊対象の変更」「死に札」「ソルバーの入力変化」に分解する対照実験は未実施。旧CPUとの因果比較、多重比較補正も未実施。
- 6,000試合で異常がないことは、無色を含む全到達可能局面での停止性の証明ではない。
