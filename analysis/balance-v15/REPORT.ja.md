勝利パターン（重複あり。全勝利を分母にした単純頻度）:

- 5ダメージで勝利: 660件（32.9%）。
- 相手のドロー時山札切れで勝利: 1,228件（61.3%）。
- 一度以上防御に成功して勝利: 1,898件（94.7%）。
- 前の手番までに防御成功があり、自分の攻撃で5ダメージ勝利: 573件（28.6%）。
- 上記のうち最終攻撃直前の自分のダメージが3以上: 262件（13.1%）。

先後の改善実験は、各対面・座席・先後を分けた層別比較と同一seedペアの対照を優先する。勝率だけでカードの強弱を断定せず、ソルバーの手札サンプリング・評価の偏りも分離して検証する。

## 8. 未検証項目と再現方法

- ミラー戦、対人戦、旧AI、旧雲雀CPUとの比較、別ソルバー設定、iPhone実機表示は対象外。
- 回復した累積ダメージ量、特定の防御が勝利を引き起こした因果効果、カード1枚ごとの寄与、勝率改善の因果効果は未測定。
- 「無限ループなし」はこの12,000試合で異常・監視上限超過がなかったという意味であり、全到達可能状態の証明ではない。
- 乱数種は各試合に独立に割当て。seed式と座席一覧はmanifest、seed・先攻（0=P1/1=P2）・勝者・決着理由・計測値はJSONLに全件保存。seedと同一ソース・同一スクリプトから再実行できる。

```sh
node analysis/balance-v15/simulate.cjs pilot 100 4
node analysis/balance-v15/simulate.cjs main 500 4
python3 analysis/balance-v15/summarize.py
```

計測を入れない通常実行との整合性検査: `node analysis/balance-v15/validate.cjs`。全20配置の予備検証先頭seedについて、勝者・理由・決着ターン・最終ダメージ／山札／手札が一致した。

Node 24以上、Python標準ライブラリのみ。再実行時は既存JSONL・manifestを別の場所に退避する（スクリプトは結果の上書きを拒否）。DOMの初期画面呼び出しだけ省き、通常と同じsetupGame/runGame/ソルバー処理を実行する。描画・待ち時間を省略しても意思決定は簡略化しない。300手番／20,000判断／worker10分の監視上限に達した場合は異常として停止し、結果を補完しない。
